## Personality and psychometric direction

Use existing game-owned state as the causal input: effective disposition, history/lesson effects, carried conditions, listener-specific relationships and current strain. SAO Disposition already bends effective traits using history, lessons and conditions; Knowledge.conditioning exports those traits alongside conditions and relationship/moment channels. A condition label and a trait already altered by that condition must not be mistaken for independent measurements of its effect.

Evaluate three distinct questions:
- Person continuity: does the same person remain recognizable across situations?
- Context response: does trust, work, threat or exhaustion change expression appropriately?
- Knowledge integrity: does changed expression preserve what that person actually knows?

Build reviewed contrasts holding facts constant while changing the relevant input. Use whole-scene review panels showing the person, situation, question, actual answer and learning consequence. Assess this as a game-grounded behavioral model; no validated psychological scale or new personality taxonomy is assumed.

## Execution discipline

- Work in coherent capability units. Keep implementation, corrections, documentation and available review receipts together through validation; publish one completed unit through the governed PR route. Independent approval subjects stay independent inside that unit.
- Reuse content-addressed evidence and append-only history. Consolidate the current navigation and continuation summary rather than rewrite old receipts or renumber batches.
- Scope verification to changed contracts during development; run every repository-required gate at publication. Avoid repeated full gates on an unchanged tree. C77's recorded full gate took 1022.7 seconds, so this is a measured source of overhead; it does not explain all elapsed time.
- Reserve UI panels for consequential behavior/voice choices. Batch independent examples into a narratively legible review session while independent implementation proceeds. Consume actual returns before recording standing.
- Keep working changes in the active worktree. Preserve the original Speakeasy checkout's pre-existing RECORD edits and SAO's local audit receipts.
- At unit start state the behavior being delivered, why it advances the project and what will settle it. During work report changed understanding and blockers. At close report usable capability, verification, limits and the next dependency.
- Track progress by eligible independent scenes, reproducible runs, task errors, grounded/personified dialogue, actual runtime consumption and measured cost. PR count, artifact count and test count describe activity, not completion.
